# config/ — words, scene files, the UI style

## Files

- `ApplicationConfig.xml` — `mode="Game"` (`"Editor"` opens the scene editor).
- `SceneConfig.xml` — the scene `MahjongScene` (`viewWidth` / `viewHeight` = `kViewWidth` / `kViewHeight`, and three `viewVariants`, in this order: `Portrait` (`orientation:portrait`), `Narrow` (`orientation:landscape;maxAspect:1.55`), `Wide` (`minAspect:2`), each with the design size of its shape: the table has four views, `Table/CLAUDE.md`) and one `<node ref="nodes/Mahjong<Name>"/>` per node; **the order is the draw and input order**. It replaces the engine's file, so it holds every scene the game uses.
- **Content version:** `SceneConfig.xml` and every node file carry `contentVersion` on the root; the engine refuses a file of another version (the scene loads empty). Never edit a format change by hand: after an engine update that bumps it run `python3 engine/tools/migrate/migrate.py .` here and commit the diff (`engine/tools/migrate/CLAUDE.md`); `TheContentFilesAreAtTheVersionOfTheEngine` holds it. A plain button is a composed `UIElement` (`UITextComponent` + `UIInputClicker`); segments and dropdown options stay `UIButton`.
- `nodes/Mahjong<Name>.xml` — one node per file (the prefix because `ConfigManager` names a config by the file stem). A new node = a file + a ref line + a row of `kSceneNodes` in `tests/MahjongSceneFilesTest.cpp`. The scene editor does not save scenes with refs: edit by hand.
- `TableLayout.xml` — the zones of the table as fractions of the design view of each shape (`src/Mahjong/Table/CLAUDE.md`, "The table layout"). The game reads it at the start and polls it while it runs: edit and save (or use the Config Editor) and the table moves; a file that fails the reader or the check is refused, the log says why, and the last good one stays. A tile size is never written: change a zone and the solver gives the tile. `<Free name="table.x">` regions are free ground for the canvases of the table, held clear of every tile by the check; the comment of each says what it stays clear of.
- `UIStrings.xml` — the string table, `en` (default) and `ru`.
- `TextureLibrary.xml` — the 43 tile sprites; **generated by `tools/make_tiles.py`, never edited by hand**.

The nodes in order with their layers: `kSceneNodes` (`tests/MahjongSceneFilesTest.cpp`).

## Words

The label `SelectedTile` (node `Hud`) says `{selectedTileText}` (key `table.selectedTile`), above the viewer's hand; the table component shows it only while a tile is selected.

The label `TileHoverLabel` (node `TileHover`) says `{tileHoverText}`, the `TileName` of the face-up tile under the pointer: it has no key of its own (`tile.*`, `suit.*`, `wind.*`).

Every visible word is a key in both languages; never a literal in code or in a `text` attribute. The scene says `text="{#key}"`, code says `Tr(strings, key, {{"n", "2"}})`. Keys of an enum family (`wind.*`, `suit.*`, `score.kind.*`, `button.*`, `hint.*`) are built in code. `StringsTest` holds parity, every key used, no plain word in a `text`, the same placeholders in both languages. Symbols (a glyph with no word) stay in code. The control API stays English. Tests that need Russian call `MahjongGame::SetLanguage` (a start re-applies the game's language) and loop with `ForEachLanguage`.

## UI style

`src/Mahjong/Table/UiPalette.h` has the names; `MahjongUiStyleTest` holds the scene to them.

- **Palette by role:** a control takes the colour of what it does — `primary` (confirms: Mahjong!, Start, Next hand, Show), `secondary` (claims, the HUD's New game), `neutral` (extras of an own turn, segments), `danger` (Pass); screens are `scrim`, a `surface` plate, a `header` band, `surfaceRaised` rows; the HUD is `hudPanel`; text white, `textMuted`, `accent`. **Marks on the table are the gold family and nothing else on the table is gold** (the dealer bar is red; the bars of the own wind and the round wind on the hand are blue and violet, the danger marks of the hints green, amber and red: roles of their own). A new colour is a new role in `kUiPalette` / `kUiPaletteNames`, never a literal.
- **Type scale:** the three sizes of `kFontScale`: small (hints, small text), middle (HUD, rows, buttons), large (headlines, main buttons). No other size.
- **Grid:** every size, offset, spacing and padding is a multiple of 4 (percents and the 21 x 28 tile pictures excepted). Margin to the view edge 8, gap 8, HUD padding 8, modal padding 16.
- **Modal anatomy:** scrim, `surface` plate (padding 16, rows 8 apart), a `header` headline band, `surfaceRaised` rows, the main button last, 64 high, 16 below the rows. Exceptions, each for a reason in `../src/Mahjong/Components/CLAUDE.md`: `HandOver` (no dim, button in a corner canvas), `Rules` (buttons in a bar), `MatchOver` (rows 4 apart to fit a 296-unit plate), `Setup` (a 56 title band, which holds the close cross as a touch target).
- **Touch size:** every control that takes input is in a `Screen` canvas with `minScale` ≥ 0.6, or in `Actions` / `HintsButton` (swapped for `ActionsCompact` in small windows; the buttons of `Actions` are 56 high, 68 in the portrait view; in the narrow view they are 84 wide in two lines right of the bottom discards, in the wide one the landscape row a wing in). `MahjongTouchSizeTest` fails a new button anywhere else.
- **Shapes:** a `SceneView` canvas on the table lays out against the active view, and an element of it **names a region** the table publishes (`region="table.hint"` with `anchor` / percents inside: the zone regions and the free ones of `TableLayout.xml`, `src/Mahjong/Table/CLAUDE.md`), never a pair of unit offsets. Its `<variants>` with `when=` the text of a view (`orientation:portrait`, `orientation:landscape;maxAspect:1.55`, `minAspect:2`; `MahjongSceneFilesTest` holds every such variant to the three; they exclude each other, so never rely on order) hold only a real difference (a size class, a hidden element, another anchor). A region wins over the safe area: the table is a fixed design, so these canvases do not move with insets. A new element needs a region (a new free one goes into every shape of the file; `CheckTableLayoutSpec` holds it clear of the tiles) and passes the rule tests of `MahjongSceneFilesTest` (it names a region or is a listed exception; the matrix against the regions). A `Screen` canvas sees the window, not the view (`HudMenu` splits the narrow windows at its own aspect).
- **Engine limits:** the renderer has filled rectangles and textures only; one font, no weight; a label's colour cannot follow a variable.
- **Adding a control:** pick the role, a font of the scale, sizes on the grid, write the palette entry as `r,g,b,a`, run `MahjongUiStyleTest`.
