# config/ — words, scene files, the UI style

## Files

- `ApplicationConfig.xml` — `mode="Game"` (`"Editor"` opens the scene editor).
- `SceneConfig.xml` — the scene `MahjongScene` (`viewWidth` / `viewHeight` = `kViewWidth` / `kViewHeight`) and one `<node ref="nodes/Mahjong<Name>"/>` per node; **the order is the draw and input order**. It replaces the engine's file, so it holds every scene the game uses.
- `nodes/Mahjong<Name>.xml` — one node per file (the prefix because `ConfigManager` names a config by the file stem). A new node = a file + a ref line + a row of `kSceneNodes` in `tests/MahjongSceneFilesTest.cpp`. The scene editor does not save scenes with refs: edit by hand.
- `UIStrings.xml` — the string table, `en` (default) and `ru`.
- `TextureLibrary.xml` — the 43 tile sprites; **generated by `tools/make_tiles.py`, never edited by hand**.

Nodes (in order): `Table`, `Hints` (5), `HintsButton` (6), `Actions`, `ActionsCompact`, `Hud`, `SeatPlates`, `HudMenu` (10), `Handoff` (20), `HandOver`, `MatchOver` (25), `HandOverAction` (26), `Setup` (30), `Rules` (35), `RulesAction` (36).

## Words

Every visible word is a key in both languages; never a literal in code or in a `text` attribute. The scene says `text="{#key}"`, code says `Tr(strings, key, {{"n", "2"}})`. Keys of an enum family (`wind.*`, `suit.*`, `score.kind.*`, `button.*`, `hint.*`) are built in code. `StringsTest` holds parity, every key used, no plain word in a `text`, the same placeholders in both languages. Symbols (the dealer `*`) stay in code. The control API stays English. Tests that need Russian call `MahjongGame::SetLanguage` (a start re-applies the game's language) and loop with `ForEachLanguage`.

## UI style

`src/Mahjong/Table/UiPalette.h` has the names; `MahjongUiStyleTest` holds the scene to them.

- **Palette by role:** a control takes the colour of what it does — `primary` (confirms: Mahjong!, Start, Next hand, Show), `secondary` (claims, the HUD's New game), `neutral` (extras of an own turn, segments), `danger` (Pass); screens are `scrim`, a `surface` plate, a `header` band, `surfaceRaised` rows; the HUD is `hudPanel`; text white, `textMuted`, `accent`. **Marks on the table are the gold family and nothing else on the table is gold** (the dealer bar is red). A new colour is a new role in `kUiPalette` / `kUiPaletteNames`, never a literal.
- **Type scale:** 18 (hints, small text), 22 (HUD, rows, buttons), 28 (headlines, main buttons). No other size.
- **Grid:** every size, offset, spacing and padding is a multiple of 4 (percents and the 21 x 28 tile pictures excepted). Margin to the view edge 8, gap 8, HUD padding 8, modal padding 16.
- **Modal anatomy:** scrim, `surface` plate (padding 16, rows 8 apart), a `header` headline band, `surfaceRaised` rows, the main button last, 64 high, 16 below the rows. Exceptions, each for a reason in `../src/Mahjong/Components/CLAUDE.md`: `HandOver` (no dim, button in a corner canvas), `Rules` (buttons in a bar), `MatchOver` (rows 4 apart to fit a 296-unit plate).
- **Touch size:** every control that takes input is in a `Screen` canvas with `minScale` ≥ 0.6, or in `Actions` / `HintsButton` (swapped for `ActionsCompact` in small windows). `MahjongTouchSizeTest` fails a new button anywhere else.
- **Engine limits:** the renderer has filled rectangles and textures only; one font, no weight; a label's colour cannot follow a variable.
- **Adding a control:** pick the role, a font of the scale, sizes on the grid, write the palette entry as `r,g,b,a`, run `MahjongUiStyleTest`.
