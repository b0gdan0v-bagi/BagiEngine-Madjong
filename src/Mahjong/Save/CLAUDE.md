# Save/ — the save of a match and of the Setup choices

Plain C++ with reflected states: `MatchSave.*` has no scene and no disk, `MatchSaveStore.*` is the disk. The game's hook is `MahjongGame` (`../CLAUDE.md`). The three slots are `SaveGameService` slots of the game id `Mahjong`, version `kMahjongSaveVersion` (min `kMahjongSaveMinVersion`), in the engine's binary envelope (`engine/src/Modules/BECore/Save/CLAUDE.md`): a new field needs no version, a field whose meaning changes does.

## What is stored: the log of the match, not the table

- **`match`** (`kMatchSlot`): the `Start`, `Action` and `Settlement` events of the match in progress (`MatchSaveText`, one `EventToJson` line each, in the one string `MahjongMatchSave::log`; no `Hand` / `End`, no breakdowns). Resuming replays them (`TableSession::ResumeMatch`, `../Game/CLAUDE.md`). The settlements stay in on purpose: the replay checks them, so a save that a change of the rules or of the wall would make differ is **refused, not guessed at**.
- **The computers' random state is not saved**: the computers are made again from the seed of the match, so play after Continue is legal and of the same level, but not bit for bit the uninterrupted game. The price of not tying a save to the computer players of the build that wrote it.
- **`settings`** (`kPrefsSlot`, `MahjongPrefsSave`): the choices of `Setup` and `Options` (`language`, `hintsOn`, `coach` (the coach mode, implies `hintsOn`; a file without it reads false), `seats` "PCCC", `hands` 16 | 8, `level`, `levels`, `speed` `slow` | `normal` | `fast`: a file without it reads Normal). `levels` is the level of each seat as text ("5,2,6,10"); empty when all four are equal, then `level` is the one level (so an old file reads as before, and `level` is always the lowest computer seat's); when it is not empty it wins, and one that is not four numbers 1..10 refuses the whole prefs slot. Never `flowers`, `limit`, `replayDrawnHand`, `startingScore`.
- **`online`** (`kOnlineSlot`, `MahjongOnlineSave`): the name the player typed (empty: none) and the session of the room to come back to, as the JSON text of `SessionToJson` (`url`, `room`, `token`; empty: no room kept). `ReadOnline` refuses, as one `Broken` slot that the game warns about once and applies none of, a name no room accepts and a session that is not a room and a token (`SessionFromJson`); the detail never repeats the token. **The token is the player's secret and this slot is a plain file under `saves/` like the others**, so it reaches no log line, notice or variable; whether a keychain is worth it is the owner's call. In the browser it is kept across a reload when the storage is remembered. Written by `FlushSave()` only when the name or the client's `SessionRevision()` moved (a session the client forgot, by `Leave` or a room that is gone, leaves the file; with no name and no session the file is removed); read by `Start()` after the prefs.

## Where

`MatchSaveDirectory()`: default `saves/` under the working directory (git-ignored), or `BAGI_MAHJONG_SAVE_DIR` when set; an empty path switches saving off (`SetMatchSaveDirectory`). **The browser build (`kBrowserBuild`, `../Platform.h`) saves to the engine's `kWebSaveDirectory` (`/bagi/saves`), which the page keeps in the site's IndexedDB** (`engine/src/Modules/BECore/Save/CLAUDE.md`, "In the browser"; the environment is ignored there), so `Continue`, the `Setup` choices and the room session survive a reload. `MatchSaveStorage()` is what the storage made of the folder (`SetMatchSaveStorage` is the seam of a test). The gtests switch it off for the whole process (the global environment of `MahjongSaveGameTest.cpp`) and the saving tests use a temporary folder; `control_smoke.py` sets the variable to a temporary folder, so no test touches the owner's `saves/`.

## When it is written

- The session's sink is a `MatchRecorder`: it forwards every event to the `MatchLogWriter` and keeps the events of the current match. **No file is written from that hook.**
- `MahjongGame::FlushSave()` writes, called by `Stop()` and once per frame by `MahjongHudComponent` (`SceneUpdateEvent`). A burst of computer steps is one write; "after every action" means "at the end of the frame that made it". A flush is cheap even for a 16-hand match, so there is no throttle.
- Each write and delete calls the engine's `NotifySaveChanged()` (inside `SaveGameService`), which flushes the folder to IndexedDB soon, at once when the tab is hidden: the last complete save is the one on disk at `pagehide`. The game adds nothing.
- It writes only a match that **is being recorded** (`IsRecording()`, not the counter alone: an unrecorded background match moves the counter too); a finished match deletes the slot, so it is never offered. The prefs are written only when they differ from the last copy written or loaded. A failed write is one warning, not retried until something changes.

## Start and Continue

- `Start()` reads the storage state once (`MatchSaveStorage()`). **`NotRemembered` (a private window, IndexedDB refused) is saving off**: the store gets no folder, so nothing is written, read or offered, and the player is not promised a `Continue` the next visit cannot keep. `SavesAreRemembered()` ("is my choice kept?": saving on and the storage remembers) is what the consent of the match upload will pass as `remembered`.
- `Start()` opens the store, applies the prefs (a prefs slot that does not check is one warning and none of it applies), then tries `match`: parse, replay on a scratch `Match`, `ResumeMatch` with the recorder on. **On success the saved match is the table behind the open `Setup` and `CanContinue()` is true**; nothing is dealt and the slot is not rewritten.
- Otherwise (no slot: silent; a broken, foreign, newer or non-replaying slot: one warning, the file stays) a random match is dealt **unrecorded** (`BeginMatch(seed, false)`), so a match behind the panel can never overwrite the saved one.
- Any match begun by `StartMatch` (`Start` of the panel, `Reset()`, a control `reset`) is recorded, clears `CanContinue()` and replaces the slot at its first flush. `ContinueMatch()` closes `Setup` and the rules; closing the panel any other way also drops the offer.
- After Continue the state is where the match was left (mid-hand, a claim window, the score table). With two people or none the viewer is nobody, so the hot-seat cover is up. The game's seats, levels and hands become those of the resumed `Start` (the levels of person seats too), so `New game` shows the choices of the match that was played.
- A folder that cannot be used is one warning; the game plays on unsaved.
