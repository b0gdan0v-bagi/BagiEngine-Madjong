# Online/ — Mahjong in a room (the server side, the client model, the screens)

`MahjongSeatedGame` is the game's `ISeatedGame` (contract: `engine/src/Modules/Games/CLAUDE.md`, "Seats"), registered by a server as `mahjong` (`MahjongSeatedGame::Info()`). It drives `Match` and `HandModel::Apply` directly, with no `TableSession`, `MahjongGame`, scene or `ImGui`: it compiles into `MahjongModule` and the headless server links it. Not here: the match log, saves (a server restart ends the rooms). The client side is "The client model" below.

- **Room seat `i` is Mahjong seat `i`.** The adapter knows no person from a computer: the room decides who is one, per seat and at any moment (a seat whose player stayed away past the grace becomes one). So it has no seat setup and no per-seat level; `level` of the options is the level of every computer seat. A claim window has several seats that decide, which `TableSession::PerformPerson` (the first only) cannot serve.
- **Options** of `Start` (untrusted): `hands` 8 or 16 (default 16), `level` 1..10. Others are ignored (`flowers` is never offered); a wrong member is `invalid_params` naming the key and changes nothing. The 64-bit room seed is the match seed `low ^ high`.
- **Order of checks** in `PerformSeatAction`: `invalid_seat`, `invalid_params` (`ActionFromJson`), `not_your_turn` (the seat has no actions now), `illegal_action` (not in the list `GetSeatActions` gives: accepted iff listed), then apply. An error changes nothing and does not bump the version.
- **The answer is public** (the contract may send it to every seat): `applied` is the action as the table shows it; a concealed kong names no tile and a `pass` has no `applied` (it would tell that the seat could claim). `settlement`, `phase` and `version` are public.
- **`next_hand` is a ready check.** In a finished hand every seat has `{"type":"next_hand"}` once; the hand is settled (`Match::EndHand`) when all four have sent it, and the answer then carries `settlement`. Computers send it through `ChooseComputerAction` (the room's delay, so an empty or abandoned seat does not hold the table), a person when they have read the end screen: without the check a computer's `next_hand` would take the end screen from the people. The flags are public (`ready`, four booleans in the view) and each one bumps the version so the view goes out.
- **A view** is the table state of `MahjongStateJson` for the seat (`MakeTableView`: its own `hand`, the public table, the counts of the others), without `kind`, `level` and `levels` (the lobby says who is a person), plus `ready` and `format` (`kOnlineViewFormat`). `result` (all four hands, the payments depend on them) appears only when the phase is not `playing`. The view reads of other hands their size only. A change here is a change of the wire format: the server and the client are deployed together. **`format`** is one integer in every view of a started game (not in `get_state` of the control API): bump it with every change of keys or meaning that an old client cannot read; a client reads exactly its own number and refuses another in words (no guessing at a table).
- **Computers are stateless.** `ChooseComputerAction(seat)` is `const`: a `ComputerPlayer` at the room's level, seeded `SeatSeed(MixSeed(matchSeed, GetStateVersion()), seat)` for that one call, chooses from `MakeTableView(hand, seat).legal`. The same state gives the same answer, a returning person loses nothing, nothing is mutated behind the room's back.
- **Version:** grows on `Start`, on every applied action (a `pass` too) and every `next_hand` flag; never goes back. So when several seats answer in one claim window, the second one's message carries the old version: `stale_action`, and a client re-sends while its action is still listed.
- **A client reads `actions`, not `turn.yourTurn`:** in `hand_over` `yourTurn` is false while `actions` lists `next_hand`.
- **Test seams** `GetMatch()` (both constness) are for tests, never for the server.
- **The proof** is `tests/MahjongRoomsTest.cpp`: a `RoomHub` plays rooms and a judge (`tests/MahjongRoomsJudge.h`) checks the schema of every text a client gets. Tiles have no ids, so the judge cannot spot a copied hand by name; the equal-views test (hidden tiles shuffled through `HandModel::Capture` / `Restore`, same view for the seat) covers what the schema cannot see. A new key in a view is a change of the judge too, in C++ and in `tests/rooms_smoke.py`. The executable `BagiMahjongServer` (`tools/server/main.cpp`, the engine's `RunRoomServer` with this game in the registry) is proved end to end by that script (ctest `BagiMahjongRoomSmoke`).

## The client model

`OnlineClient` owns one engine `RoomClient` (contract and numbers: `engine/src/Modules/RoomClient/CLAUDE.md`) and turns it into what a screen reads. It knows no ImGui, scene, renderer, `MahjongGame` or `GameManager`; the screens below read it, the table of a started game does not yet. A component calls `Update()` once per frame and redraws when `Version()` moved.

| File | Purpose |
|------|---------|
| `OnlineTable.h/.cpp` | `ReadOnlineView(view, actions, out, scratch)`: the server's `view` and `actions` (untrusted JSON, checked helpers) into plain data with the game's value types; errors name the key; `out` is touched only on success, and both tables keep their lists' capacity |
| `OnlineWords.h/.cpp` | every code the client can meet (`kKnownOnlineCodes`) with its key in `config/UIStrings.xml` (`online.*`); several codes share a key where the player can do nothing different; `stale_action` alone is silent |
| `OnlineClient.h/.cpp` | the model, and `SessionToJson` / `SessionFromJson` |
| `TextEntry.h/.cpp` | one bounded text (a room code or a name), its pad of keys, `CharFromKeycode` |
| `OnlineMirror.h/.cpp` | the table of a view as a display copy (below) |
| `OnlineScreens.h/.cpp` | the pages and fields over the client, pure |
| `OnlineServerUrl.h/.cpp` | the address of the server |

- **Stage** (`OnlineStage`) is derived, never stored on its own: `Idle` (no connection, or a request answered with an error), `Connecting` (a Host / Join waits for `joined`), `Lobby` (in a room, no good view yet), `Game` (a good view arrived; `Table()`), `Reconnecting` (the lobby and the table stay readable, frozen). A connection with no room and no request pending is closed by the model, so the server never closes it later with a notice nobody asked for.
- **A client reads `actions`.** `Act(i)` sends `Table().actions[i]`'s original JSON (`RoomClient::GetActions()[i]`) with the version of the last view, only in `Game` and only while `Table()` is that last view (after a view that did not read, the client already holds the new list and the screen the old table: `Act` is refused, no notice, until a good view); it is never resent (`stale_action` is silent and the fresh view follows). `view {}` before the start is not a table.
- **`format`:** the model reads exactly `kOnlineViewFormat`. Another number (or none) is `online.error.viewFormat`, the connection is closed and the session forgotten (reconnecting would get the same answer). A view that is broken in another way keeps the last good table and says `online.error.badView`.
- **Version rule:** `Version()` grows when the stage, lobby, table, notice or session to keep changes; a frame with nothing to do changes nothing and allocates nothing (lists are members). The lobby is rebuilt on a lobby event and when the client's seat or host flag moved (`ChooseSeat` takes the seat at once, an error gives it back).
- **Notice:** one `OnlineNotice` (a key, an `arg` for the one key that names a code, a serial so a screen shows each once). A command that cannot be sent, a server `error`, a `left` the player did not ask for and a `Closed` make one. The `arg` is a code from the server, reduced to letters, digits and `_`. A `Closed` the model asked for (`Disconnect`, a bad format) is dropped.
- **The session to keep:** `SessionToKeep()` with `SessionRevision()` (grows when it should be saved or erased). Forgotten on `room_gone`, `replaced`, `gave_up`, `Leave()`, a `left` and a format mismatch; kept through a lost connection, `Disconnect()` and every other close. **The token is the player's secret:** never in a log, a notice or a test message. Where it is stored (`Save/`, the browser) is the screens' decision; the model gives the data and a JSON pair that refuses anything that is not a room and a token.

## The display copy

The online table is drawn by the scene components of the local game, which read `Match` / `HandModel` / `TableSession`. So `MakeDisplayState(OnlineTable, OnlineLobby)` turns a view into the arguments of `HandModel::ForDisplay`, `Match::ShowRemote` and `TableSession::ShowRemote` (`Game/CLAUDE.md`, "Display copies") and `ShowOnlineTable` puts them in. **Not `Restore`:** a client does not know the other hands or the wall (so the counts never add up) nor the claims of the other seats, and `Restore` refuses such a state; a display model is read, never played.

- **Real:** the own concealed tiles and melds, open melds, bonus tiles, the pile, scores, turn, winds (from `east`), and, once the hand is over, all four hands and the result. **Invalid tiles:** the other hands, their concealed kongs (a `Kong` meld after the open ones), the live wall, the reserve and the dead wall. The reserve is derived from the tile count, so `Remaining()` (the wall ring) equals the model's.
- **Claim window:** the own seat is `Waiting` when `actions` lists a claim or a pass, else `Passed`; the others `Passed` (a view does not say), no `LastClaimWindow`.
- **The view does not say, so the copy does not know:** which tile was drawn (`DrawnTile` is invalid for every seat: no tint of the drawn tile, no draw flight online), `callingAtDiscardCount` (set so it is never "the first hand"), the level of a computer (all default) and the breakdown of a win. Do not score a display model; read `result.scores` and `deltas`. After the last hand `Match::East()` is the next dealer, as in a local match.
- **`IsAnotherTable(TableKey, TableKey)`** tells a new hand or match (other `handsPlayed`, east, seat, a version that went back, a played hand after an ended one: a replayed drawn hand has the same keys) from another view of the same table: the session's `StartCount()` moves on the first only.

## The screens

`OnlineScreens` is the pure model of the online panel (`Components/MahjongOnlineComponent`, the nodes `Online` and `OnlineEntry`): the page (`Menu`, `Host`, `Join`, `Entry`, `Lobby`), the two fields, the host's options and the pad. It takes the client as an argument of each command and of `Sync` and keeps no copy of it, so it holds no token; `Resume` takes the session from the caller.

- **No text field exists in the engine**, so a field is typed on a **pad of buttons** (it works on a phone and in the browser) and, on a desktop, from the keyboard (`CharFromKeycode`, ASCII). The code pad is the server's `kRoomCodeAlphabet`; the name pad is the key `online.pad.letters` of the language (letters are words, not code) plus digits and a space. The field takes the letters of both alphabets, so a name typed in one language survives a switch. A Cyrillic name from a hardware keyboard needs the engine to call `SDL_StartTextInput`; it does not yet.
- **Entry is a page, not a field:** on a window 320 units high a form and a pad of touch-size keys do not fit together. A tap on the Name or Code row opens the pad; Done returns. Escape goes one page back; **in the `Lobby` it does nothing** (a stray key must not give up a seat; `Leave` is a button).
- **The panel follows the stage of the client** (`Sync` after every `Update()`): Connecting, Lobby, Game and Reconnecting show the `Lobby` page (a lost connection is a status line, never an error); an `Idle` client after a request returns to the form it was sent from, after a room (gone, replaced, left) to the `Menu`. The `Game` stage shows the lobby with "The game has started" and `Leave`: the placeholder that the online table replaces. An error is the notice of the client in the current language, shown once per serial and cleared by the player's next move.
- **The name and the session** are the game's to keep (`MahjongGame::StoredOnline()`, `Save/CLAUDE.md`): the component hands them over, `Return` offers the client's own session, else the stored one. The address is not typed: `OnlineServerUrl` is `BAGI_MAHJONG_SERVER` on a desktop, else the default port of `BagiMahjongServer` on this machine; the browser's `wss://` one is not set yet.
- **A room in a lobby vanishes with its last member**, so `Return` works for a started game only (or while another person is in the room).
- **Known engine fault** (not worked around): `RoomClient::_host` is recomputed on `lobby` and `view` only, so a host whose `choose_seat` is refused after a `lobby` that took the seat looks like a guest until the next lobby message. A guest is unaffected.
