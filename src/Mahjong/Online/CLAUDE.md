# Online/ — Mahjong in a room (the server side)

`MahjongSeatedGame` is the game's `ISeatedGame` (contract: `engine/src/Modules/Games/CLAUDE.md`, "Seats"), registered by a server as `mahjong` (`MahjongSeatedGame::Info()`). It drives `Match` and `HandModel::Apply` directly, with no `TableSession`, `MahjongGame`, scene or `ImGui`: it compiles into `MahjongModule` and the headless server links it. Not here: the match log, saves (a server restart ends the rooms), the client.

- **Room seat `i` is Mahjong seat `i`.** The adapter knows no person from a computer: the room decides who is one, per seat and at any moment (a seat whose player stayed away past the grace becomes one). So it has no seat setup and no per-seat level; `level` of the options is the level of every computer seat. A claim window has several seats that decide, which `TableSession::PerformPerson` (the first only) cannot serve.
- **Options** of `Start` (untrusted): `hands` 8 or 16 (default 16), `level` 1..10. Others are ignored (`flowers` is never offered); a wrong member is `invalid_params` naming the key and changes nothing. The 64-bit room seed is the match seed `low ^ high`.
- **Order of checks** in `PerformSeatAction`: `invalid_seat`, `invalid_params` (`ActionFromJson`), `not_your_turn` (the seat has no actions now), `illegal_action` (not in the list `GetSeatActions` gives: accepted iff listed), then apply. An error changes nothing and does not bump the version.
- **The answer is public** (the contract may send it to every seat): `applied` is the action as the table shows it; a concealed kong names no tile and a `pass` has no `applied` (it would tell that the seat could claim). `settlement`, `phase` and `version` are public.
- **`next_hand` is a ready check.** In a finished hand every seat has `{"type":"next_hand"}` once; the hand is settled (`Match::EndHand`) when all four have sent it, and the answer then carries `settlement`. Computers send it through `ChooseComputerAction` (the room's delay, so an empty or abandoned seat does not hold the table), a person when they have read the end screen: without the check a computer's `next_hand` would take the end screen from the people. The flags are public (`ready`, four booleans in the view) and each one bumps the version so the view goes out.
- **A view** is the table state of `MahjongStateJson` for the seat (`MakeTableView`: its own `hand`, the public table, the counts of the others), without `kind`, `level` and `levels` (the lobby says who is a person), plus `ready` and `format` (`kOnlineViewFormat`). `result` (all four hands, the payments depend on them) appears only when the phase is not `playing`. The view reads of other hands their size only. A change here is a change of the wire format: the server and the client are deployed together. **`format`** is one integer in every view of a started game (not in `get_state` of the control API): bump it with every change of keys or meaning that an old client cannot read; a client reads exactly its own number and refuses another in words (no guessing at a table).
- **Computers are stateless.** `ChooseComputerAction(seat)` is `const`: a `ComputerPlayer` at the room's level, seeded `SeatSeed(MixSeed(matchSeed, GetStateVersion()), seat)` for that one call, chooses from `MakeTableView(hand, seat).legal`. The same state gives the same answer, a returning person loses nothing, nothing is mutated behind the room's back.
- **Version:** grows on `Start`, on every applied action (a `pass` too) and every `next_hand` flag; never goes back. So when several seats answer in one claim window, the second one's message carries the old version: `stale_action`, and a client re-sends while its action is still listed.
- **A client reads `actions`, not `turn.yourTurn`:** in `hand_over` `yourTurn` is false while `actions` lists `next_hand`.
- **Test seams** `GetMatch()` (both constness) are for tests, never for the server.
- **The proof** is `tests/MahjongRoomsTest.cpp`: a `RoomHub` plays rooms and a judge (`tests/MahjongRoomsJudge.h`) checks the schema of every text a client gets. Tiles have no ids, so the judge cannot spot a copied hand by name; the equal-views test (hidden tiles shuffled through `HandModel::Capture` / `Restore`, same view for the seat) covers what the schema cannot see. A new key in a view is a change of the judge too, in C++ and in `tests/rooms_smoke.py`. The executable `BagiMahjongServer` (`tools/server/main.cpp`, the engine's `RunRoomServer` with this game in the registry) is proved end to end by that script (ctest `BagiMahjongRoomSmoke`).
