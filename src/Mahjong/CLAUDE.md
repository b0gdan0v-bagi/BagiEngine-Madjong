# src/Mahjong — the game object, the control API, the match log

Subfolders have their own `CLAUDE.md`: `Game/` (the rules), `Online/` (the seated game of a room server), `Save/` (save and Continue), `Table/` (pure scene logic), `Components/` (the scene), `Arena/` (bot measurement), `Analyzer/` (the EV of a position).

## MahjongGame

`IGame` named `Mahjong`, scene `MahjongScene`. Owns, in this order, the `Match`, the `TableSession` over it, the `MatchLogWriter` (fed through the `MatchRecorder`, the session's log sink, and the `MatchUploader`, see "Upload buffer"), the save store and the control adapter. `FlushSave()`, `CanContinue()` / `ContinueMatch()`, `SavesAreRemembered()` (the one thing the match upload's consent needs; false in a browser that does not keep its storage): `Save/CLAUDE.md`. The constructor stamps the session's log origin (`BuildInfo.h`: `MakeMatchOrigin(kBrowserBuild)`, `kGameVersion` bumped by hand, `BuildId()` the short git hash that `CMakeLists.txt` read at the last `cmake --preset`, so stale until the next one; only `BuildInfo.cpp` gets it as a define). `GetUpload()` is the uploader the web glue (`MahjongUploadComponent`) gives a sink and the consent (nothing is recorded until both are set; on a desktop they never are); the game draws the match id (32 hex digits from `std::random_device`, as the seed is) and `Stop()` gives a running match up. Components reach it through `MahjongGame::GetActive()` and must check it is the active game; they read `GetMatch()` / `GetSession()`. `Start()` applies the saved `Setup` choices and offers a saved match (`Save/CLAUDE.md`); `Start()` / `Reset()` begin a match from a random seed (`std::random_device`, the only place a seed is chosen); `StartMatch(seed)` replays one. Kept across `Reset()` and `StartMatch`: `GetSettings()`, `GetSeats()`, `GetLevels()` (one per seat; `SetLevel` sets all four), `GetLanguage()` (applied to the string table at every start), `GetHintsMode()` (`Off | Hints | Coach`, the player's own choice; `HintsOn()` is "not Off"; the `CoachLedger`, the session's move observer, is enabled exactly in Coach: `Table/CLAUDE.md`), `GetAnimationSpeed()` (the pace of the table, no rule: the control API ignores it). Whether a hint is on screen is `HintsActive()` / `CoachActive()` (`EffectiveHintsMode()`): the own choice outside a room, in a room Off unless the host allowed hints. UI flags: `IsSetupOpen()` (`Start()` opens it; any start and any accepted control action close it), `IsOptionsOpen()` (the page `Options` over the table, opened by the HUD button; also closed by `CloseSetup()`, so by any start, `Continue` and any accepted control action), `IsRulesOpen()`, `IsOnlineOpen()`, `IsTablePaused()` (any of the four is open).

**Online:** `GetOnline()` makes the `OnlineClient` (`Online/CLAUDE.md`) on first use and it lives as long as the game, so the screens and the table of a room read the same one; `SetOnlineSettings` is the seam for a test transport and is refused once the client exists. `IsOnlineOpen()` is a flag of its own that `CloseSetup()` does not clear (closing the online panel gives `Setup` and its `Continue` offer back); `Start()` and `Stop()` close it. `StoredOnline()` is the name and the session to offer `Return` for: read from the `online` slot at `Start()`, then following the client's session (`FlushSave()`, `Save/CLAUDE.md`); `SetOnlineName` changes the name.

**The display pair:** the game owns a second `Match` / `TableSession` (+ `MoveTracker`) next to the local ones, a display copy of the room's table (`Online/CLAUDE.md`, "The display copy"). `SyncOnlineTable()` (the online component calls it right after `GetOnline().Update()`; work only when `OnlineClient::Version()` moved) fills it, and `IsOnlineTable()` is true while the client has a table in `Game` or frozen in `Reconnecting`. Then `GetMatch()` / `GetSession()` return the display pair, and `GetCoach()` the room's own ledger (`CoachContext()` keys it: the match is a table of the room, since the display session's `StartCount()` moves with every hand), so the components draw the room unchanged, and **everything of this machine's game uses `GetLocalMatch()` / `GetLocalSession()` or the members**: `Start`, `StartMatch`, `ContinueMatch`, the recorder, the match log, the upload, `FlushSave()` (writes no match meanwhile; the slot stays for `Continue`) and the control API. The table going live closes `Setup`, the rules and the online panel (the offer of `Continue` stays); it ending (`Leave`, room gone, a bad format) opens `Setup` over the local game as it was, and with a notice of the client that the player did not ask for (`Leave` makes none) also the online panel, which shows it (`TakeRoomEndNotice()`). `Start()` forgets a table shown, a client still in a room shows it again at the next sync.

## ComputerThinking

`ComputerThinking` runs the search of one `ComputerStepJob` (`Game/TableSession.h`) as a background task for the table component: `Start(job)`, `TakeFinished()` polled once a frame, `Drop()`; the destructor drops. A job that needs no search starts no task and is finished at once. **The task captures only its shared state** (result slot, done flag with release / acquire, the `CancellationToken`) and its own copy of the job, never the owner, the session or the game, so a dropped run, or one that outlives its owner, ends by itself and frees its frame; every `Start` makes a state of its own, so an answer of an earlier run is never handed out. Its loop checks the token, then `co_await YieldIfNeeded()`, then plays one rollout. The main thread only polls: no `Wait()` (it deadlocks in the single-thread build), no `SwitchToMainThread`.

## Control API

`MahjongGameControl` (`AsControllable()`): `get_state`, `list_actions`, `perform_action`, `reset` of the engine's game control (`engine/src/Modules/Games/CLAUDE.md`). `set_state` is unsupported; `no_active_model` before the first match. While `IsOnlineTable()` every call answers `no_active_model` (the adapter drives the local match only). A client plays the **person seats**; after each action the adapter calls `RunComputers()`. With no person seat (`"seats": "CCCC"`) `reset` and `next_hand` play each hand to its end and the client is a spectator.

- **State** is built by `MahjongStateJson` (`TableStateToJson`, shared with the online view of `Online/`; `kind`, `level` and `levels` are written only when the caller gives them). It is the view of the person to act, else of the first person (`MakeTableView`), so a client never sees more than a computer could. Keys: `phase` (`playing` | `hand_over` | `match_over`), `seat`, `seatWind`, `roundWind`, `east`, `hand`, `turn` {`phase`, `current`, `pendingTile`, `yourTurn`}, `seats` (kind, wind, score, `concealedCount`, melds, `concealedKongs`, bonus, `discardCount`, `calling`), `discards`, `wall`, `level` (the lowest computer seat's, for clients that know one level), `levels` (four numbers, one per seat, a person's too), `handsPlayed`, `handsTotal`, `version`, and once a hand is over `result` (all four hands, breakdowns, scores, deltas). A client reads `yourTurn`.
- **Actions** (`ActionToJson` / `ActionFromJson`): `discard` {`tile`, `declareCalling`}, `win`, `concealed_kong` / `upgrade_kong` {`tile`}, `claim` {`claim`: `chow` (+ `first`) | `pung` | `kong` | `mahjong`}, `pass`, `next_hand` (only in `hand_over`). `illegal_action` = well-formed but not listed; `invalid_params` = malformed. Client data goes through the checked helpers of `BECore/Control/Json.h`.
- **`reset`** `{seed, seats "PCCC", hands 8|16, flowers, level 1..10 (all four seats), levels [1..10 x 4]}`, all optional; given values are kept for the next match; anything invalid changes nothing. `level` and `levels` together are `invalid_params`.
- Output is English in every language (ids, notation). `GetStateVersion()` is `TableSession::Version()`.
- Smoke test: `tests/control_smoke.py` (ctest `BagiMahjongControlSmoke`).

## Match log

- **JSON** (`MatchLogJson`): one object per line, key `event` (`start`, `hand`, `action`, `settlement`, `end`); tiles in notation, winds by name, seats 0..3; `action` is exactly `ActionToJson`. `kMatchLogFormatVersion` 6: `start` has the optional `nickname` (written only when a tester typed one and agreed to send; at most 24 bytes, no control character, else refused; versions 1..5 read as none, and an older `start` that carries one is not looked at); version 5 has the origin of the match, `platform` (`desktop` | `web` | `unknown`), `build` and `gameVersion` (strings; versions 1..4 read as `unknown`, empty, empty); version 4 has `levels`, four numbers 1..10, one per seat, a person's seat too; version 3 wrote one `level` number (read as four equal levels); version 2 wrote the names `easy` / `normal` (read as 1 / 5, and `hard`, `kMatchLogRetiredLevelName`, as 5); version 1 has no level and reads as Normal. Reading is checked and errors name the member and the line.
- **File** (`MatchLogWriter`): one file per match, `logs/matches/<local time>_seed<seed>.jsonl` under the working directory (`-2`, `-3` on a clash; `std::ios::noreplace`, never overwritten), flushed per line, opened at `Start`, closed at `End` / next `Start`. `SetMatchLogDirectory("")` switches it off. Off by default in the browser build (`Platform.h`). It never fails the game: a problem is one warning. The gtests point it at a temp folder for the whole process (`MatchLogFileTest`); the smoke test's game writes into the build folder.

## Upload buffer

`MatchUpload.h`: `MatchUploader` is a match log sink (in the chain, forwarding every event to `next`) that keeps the match in progress in memory, cut in `UploadPiece`s, for an `IMatchUploadSink`; no network, no JSON of its own (`EventToJson`). **Off (consent `Unasked` or `Declined`, no sink, no id source) means nothing is buffered and nothing leaves**, decided at the match's `Start`: a consent granted mid-match records the next match (a log without its `Start` would not replay), a consent withdrawn or a sink taken away drops the buffer with no `Abandoned` piece. A piece is cut after each `Settlement` (`Open`) and at `End` (`Ended`); a new `Start` or `Abandon()` sends the rest as `Abandoned` (empty too). **A saved match that `Continue` resumes is not uploaded** (`ResumeSavedMatch` sets recording off: its replay would record the match again under a new id, and the part played before cannot be rejoined); it goes on being saved, and the next `StartMatch` records again. `lines` are exactly the bytes `MatchLogWriter` writes, so `AssemblePieces` (shared with the store side) gives the file. A piece holds the match id (chosen by the caller, never the seed), the index, the lines, the end and `consentRemembered` (false: the choice is asked again at the next visit); nothing about the person or the machine, a test pins the member list.

## Upload sink

`WebUploadSink.h`: the `IMatchUploadSink` that posts each piece to `POST /matches/<matchId>/<index>` (an empty `lines`, the marker of a match given up, is an empty body, which the server stores) through `IWebPoster` (`EngineWebPoster` forwards to the engine's `WebPostStart` / `WebPostPoll`; a test brings a fake). The scene component calls `Pump(now)` once a frame (the clock is a parameter) and `Flush` when the game stops. **One post in flight, pieces strictly in order** (the server wants piece 0 first); a piece stays at the front of the queue until it is answered. 2xx done; 408 / 429 / 5xx / no answer retry the same piece (back-off 60 s doubling to 10 min); 401 and 404 disable the sink for the session (`State()`), the queue is dropped; any other answer, a piece over 1 MiB and a bad path drop **that match** (what still arrives of it too) and the next match goes on. The queue is bounded (64 pieces, 4 MiB): beyond it the oldest match waiting is dropped whole. A poster that is not `Available()` (desktop) queues nothing. `Flush` posts what waits without the answers; `keepalive` covers a body up to 60000 bytes only, so a bigger piece may not outlive a closing tab.

**The tester's choice** (`UploadPrefs.h`): consent plus an optional nickname (the `Name` rules of `TextEntry`) in `upload.txt` of `UploadPrefsFolder()` (the engine's persistent browser folder; empty, so nowhere, on a desktop), written through a temp name and a rename, then `NotifySaveChanged()`. Not a `.save` slot, so the game's saves never list it. A damaged file reads as the defaults (`Unasked`), never as an error. `SavesAreRemembered()` of the game is `consentRemembered` of the pieces: false when the page cannot keep the folder, and the screen then comes back at each visit. `MahjongGame::GetUploadPrefs()` is a plain member for the scene's components.
