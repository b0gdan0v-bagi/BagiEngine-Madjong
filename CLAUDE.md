# Mahjong Module Guidelines

## Overview

`MahjongGame` is an `IGame` (name `Mahjong`, scene `MahjongScene`). Executable `BagiMahjong`, module `MahjongModule`, tests `MahjongTests`. Namespace `BECore::Mahjong`. Infrastructure and how a game is registered: `engine/src/Modules/Games/CLAUDE.md`; how this repository was set up around the engine: `engine/NEW_GAME.md` (on the engine's `main`).

**State: stages 1-2 of the rules exist, nothing else yet.** The game is registered, starts in Game mode (`mode="Game"` in `config/ApplicationConfig.xml`; set `mode="Editor"` to open it in the scene editor) and shows its scene with a title. `Game/` holds the rules of classic Chinese mahjong for four seats as plain C++, from the tiles to a finished hand: the tile set, the seeded RNG, the seats, the wall, the deal, the hand shape and `HandModel` (turns, claims, the three kongs, robbing, winning, the drawn hand, the list of legal actions). Scoring, the match (hands, the move of the winds), the computer players, the control API and the scene (components, assets, HUD) are next; `MahjongGame` does not use the model yet.

## Wall conventions

The break, the loose tiles and the dead wall are assumptions of this repository (`Wall.h` has the details; the numbers are named constants). The ring is four sides of 17 stacks of two tiles (18 stacks with flowers). East rolls 2d6 `a`: side `(a - 1) % 4` counted from East's own wall is broken; the owner of that side rolls `b`; the break is after `a + b` stacks from the right end of that side. The sides lie clockwise in the ring, so a count that runs past the left end of a side goes on into the wall of the clockwise neighbour, as on a real table, and `GetBreak().index` is the physical position of the break. Drawing starts at the break. The first 2 tiles are the loose reserve (a loose draw is refilled from the live tail), the last 14 are the dead wall and are never drawn.

## HandModel

`Game/HandModel.h` plays one hand; the wall is built outside (`Begin(settings, wall, seatWinds, roundWind)` deals and gives East the first tile). The phase (`Phase`) is `Discard` (the current seat holds one tile too many and acts), `Claim` (a discard is pending and the other seats decide), `RobKong` (an upgraded kong is pending, the other seats may only claim mahjong) or `Finished`. A draw is automatic: every transition that ends in a draw performs it (`Receive`), so a seat only sees a phase it can act in. A drawn bonus tile is laid open and replaced from the loose reserve, again and again; no tile to draw (an empty live wall when a draw is due, an empty reserve when a replacement is due) ends the hand as `ResultKind::Drawn`. Actions (`Discard(seat, tile, declareCalling)`, `DeclareWin(seat)`) return `std::expected<void, HandError>`; a refused action changes nothing. Nothing is compulsory: a seat that could win discards instead if it wants. The calling hand is declared with a discard (`declareCalling`): the 13 tiles that stay must be waiting (`WinningTiles(PlayerHand)`, the copies in the seat's melds counted); `callingAtDiscardCount` is the number of earlier discards of the seat, so "declared in the first hand" is `== 0`; the declaration is not binding afterwards. A self-draw win (`DeclareWin`) needs the declaration and a winning shape and ends the hand with `HandResult { Win, winner, winningTile, WinSource::SelfDraw, from, loose, lastLiveTile }`: `loose` when the tile came from the loose reserve, `lastLiveTile` when the live wall is empty after it. The shared pile is `Discards()`. Claims: a discard opens `Phase::Claim` only when some other seat has a legal claim (`LegalClaims(seat)`: `ClaimOption { ClaimKind Chow | Pung | Kong | Mahjong, chowFirst }`); otherwise the next seat draws at once. A seat in the window (`PendingClaimSeats()`, `GetClaimStatus`) decides once: `Claim(seat, kind, chowFirst)` or `Pass(seat)` (always allowed; a second decision is `AlreadyDecided`, a seat outside the window `NotYourTurn`, a claim it cannot make `IllegalClaim`). A chow only for the seat after the discarder (`chowFirst` is the lowest tile of the chosen sequence, a seat may have several; never honours, never wrapping); a pung needs two equal tiles, a kong three; mahjong needs the calling-hand declaration (`NotCalling`) and a winning shape with the tile (`CannotWin`). When every seat in the window has decided the best claim wins: mahjong, then pung or kong, then chow; two mahjong claims go to the seat farther counter-clockwise from the discarder (`Offset` larger). The claimed tile leaves the pile and goes into an open `Meld` (`fromDiscard`, `from`, `claimed`); the claimer then discards without drawing (`DeclareWin` is refused: no drawn tile), after a kong it first draws a loose tile, and the turn after its discard goes to the seat after the claimer (seats are skipped). All pass: the seat after the discarder draws. A mahjong claim ends the hand with `WinSource::Discard`, `from` the discarder, the tile joins the winner's concealed tiles. In `Claim` `CurrentSeat()` is the discarder and the pending tile is `Discards().back()`. Kongs of the own turn: `DeclareConcealedKong(seat, tile)` turns four equal concealed tiles into a concealed `Meld` (four tiles left in the hand are no kong; the declaration is never compulsory), `UpgradeKong(seat, tile)` adds the fourth tile to an open pung (the meld turns into a `Kong`); both are refused with `IllegalKong` when the hand does not allow them, and both draw a loose tile (`Receive(seat, DrawLoose(), true)`: a bonus tile is replaced again, an empty reserve ends the hand as drawn) before the seat discards. An upgraded kong can be robbed, only to win: when another seat has declared a calling hand that the tile completes, `Phase::RobKong` opens (`CurrentSeat()` is the kong's owner, `PendingTile()` the tile), those seats `Claim(seat, ClaimKind::Mahjong)` or `Pass`, the farther one counter-clockwise from the owner wins, the hand ends with `WinSource::RobbedKong` and `from` the owner, the tile is taken from the kong (the owner keeps a pung); if nobody robs, the kong is completed. A win on a tile from the reserve has `loose` (after a kong or a bonus replacement); a refill that empties the live wall sets `lastLiveTile` as well. `AfterDiscard` decides what follows a discard and `Receive` gives a seat a tile. `PendingTile()` is valid only while a window is open (it is reset when the window closes).

Actions as data (the surface of the computer player and the control API): `HandAction { ActionKind Discard | DeclareWin | ConcealedKong | UpgradeKong | Claim | Pass, tile, declareCalling, claim, chowFirst }` with the factories `MakeDiscard`, `MakeDeclareWin`, `MakeConcealedKong`, `MakeUpgradeKong`, `MakeClaim`, `MakePass`. `LegalActions(seat)` lists what the seat can do now: on its turn a `Discard` of each distinct concealed tile (and the same with `declareCalling` where the rest is waiting), `DeclareWin`, a `ConcealedKong` for each tile held four times, an `UpgradeKong` for each open pung whose tile is in the hand; in `Claim` / `RobKong` the `LegalClaims` plus `Pass` for a seat that has not decided; empty for every other seat, after the end, and for a number that is no seat. `Apply(seat, action)` dispatches to the method of the kind; an action that is not in the list is refused with that method's error and changes nothing. `Claim` asks first whether the seat is in the window (`NotYourTurn`), only then about the declaration (`NotCalling` / `CannotWin`). `Begin` returns `BadSeatWinds` (and changes nothing) unless the winds hold East exactly once; a model that was never begun is a finished, drawn hand, so a result exists exactly when the phase is `Finished`. `GetHand` and `SeatWind` take a real seat (`IsSeat`); `GetClaimStatus` answers `NotInWindow` for any other number.

## Rules for the code to come

- The rules live in `Game/` as plain C++ that a test drives without a scene; `MahjongGame` owns the model, components read it through `MahjongGame::GetActive()` and check that the game is the active one (`engine/src/Modules/Games/CLAUDE.md`, "Gotchas").
- Components subscribe with `SubscribeInScene`; there is no per-frame hook in `IGame`, per-frame work belongs in a component.
- No `ImGui::` in a game component without `ImGui::GetCurrentContext()`: the HUD and the menus are UI canvases of the engine (`engine/src/Modules/BECore/UI/CLAUDE.md`).
- A control API is an `IControllableGame` adapter next to the game, returned from `AsControllable()`; with it comes `be_add_game_control_tests(BagiMahjong ...)` in `CMakeLists.txt`.
- New or moved sources, and every change to a file with `BE_CLASS` / `BE_REFLECT_FIELD`, need `cmake --preset <p>` again (sources are globbed, reflection is generated at configure time).

`tests/FixedWall.h` (header only) lays out a wall tile by tile for the tests of the hand: `FixedWallSpec { hands[4] (13 tiles per seat in deal order), live, loose, liveAfterDeal }`, `MakeFixedWall(spec, flowers, east = 0)` and `MakeModel(spec, east = 0, roundWind, flowers)` (a started `HandModel` on that wall); whatever the spec leaves out is padded from the set (never more than four of a kind; a spec that asks for more fails the test). Use it for every test that needs to know what a seat holds or draws.
