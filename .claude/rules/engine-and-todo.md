# The engine submodule and the todo store

This repository is a game (Mahjong) that carries the BagiEngine as the git submodule `engine/`. The skills `todo-loop`, `todo-merge`, `todo-add`, `todo-db` and the agents `todo-*` work the entries of the **todo store** (`engine/tools/todo/CLAUDE.md`): a service on Railway over Postgres that holds the entries of both areas (`mahjong` and `engine`), their status, the plans and the reviews. Nothing of it is in git.

- **Style and contract:** the code style, DO and DON'T, the architecture and the `be_*` CMake functions are the engine's: read `engine/CLAUDE.md` and the nested `CLAUDE.md` files under `engine/src/` when a file there is read. The game's own `CLAUDE.md` (the root of this repository) comes first for anything about Mahjong; `README.md` has the build commands.
- **Tools come from the engine:** `python3 engine/tools/todo/todo.py` (standard library only, no venv) from the root of this repository; `TODO_API_URL` and `TODO_API_TOKEN` are in the git-ignored `.env` (`.env.example`). There is no copy of the tool here.
- **The engine is developed from here.** The game is the proving ground of the engine, so engine work is done in this checkout, in the `engine/` submodule: an entry of the area `engine` is worked by `todo-loop` in a branch `todo/<id>` of the engine repository (cut from `games/mahjong`), and the work is tried live by building `BagiMahjong` with the engine on that branch. The vendored code (`engine/src/Modules/EABase/`, `EnTT/`, `fmt/`, ...) and `engine/external/` stay untouched. The areas (game and engine: todo folder, repository, base branch, tracker project) are in `.claude/rules/todo-project.md`.
- **The pointer of `engine/`.** The loop never moves it. `todo-merge` does, after the merge of an engine branch into `games/mahjong` and the owner's yes, as a commit of its own (`Update engine: <title>`); a pointer changed by hand is the owner's commit. While an engine branch is checked out, `git status` of this repository shows `engine` as modified; that is expected.
- **Parallel loops** run in worker folders beside this checkout (`../BagiEngine-Madjong.workers/w<k>`, made by `engine/tools/todo/worker.py`; `todo-project.md`, "Workers"). They are git worktrees of this repository, and each `engine/` there is a worktree of this checkout's engine module, so every `todo/*` branch of both repositories is visible here. Never run `git submodule update` in a worker's game repository (`worker.py check` finds and `check --fix` repairs what it would break: the `core.worktree` of the engine module).
- **Skills and agents are one copy.** `.claude/skills/{build,clang-format,strip-pch-includes,todo-loop,todo-loop-parallel,todo-merge,todo-add,todo-db}` and `.claude/agents/todo-*.md` are symlinks into `engine/.claude/` (they need the submodule initialised). Change them there, in the engine repository; what differs between the repositories is in `.claude/rules/todo-project.md` (the todo areas) and `.claude/rules/build-project.md` (build, format and includes: the presets, the test targets, the source paths, the failure hints).
- **The engine branch:** `engine/` follows the permanent branch `games/mahjong` of BagiEngine (`branch = games/mahjong` in `.gitmodules`), not `main`. It is the base branch of engine work: branches `todo/<id>` are cut from it and merged back into it. The owner merges `main` into it when the game should get newer engine work. `git submodule update --remote engine` brings the tip, and the new pointer is committed on its own.
- **Vikunja:** two projects, one per area: `BagiEngine-Madjong` for `mahjong` and `BagiEngine` for `engine`. The service mirrors every change of the store into them and takes back what a person changes there (webhooks and a reconcile pass), so **nobody runs a push or a pull**: the Vikunja token lives in the service (Railway), not in this `.env`. Which project belongs to which area is a setting of the store (`todo.py area list`).
- **Plans** (the owner's, the loop's slice plans and the reviews) live in the todo store and are **never committed**; their working copies are in `~/.claude/plans/`, outside every repository (`todo.py plan get` / `put` refuse a path inside a git work tree, and `.gitignore` keeps `.claude/plans/`, `*.plan.md` and `todo-export/` out).
