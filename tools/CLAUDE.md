# tools/

- `arena/main.cpp` — `BagiMahjongArena`, see `src/Mahjong/Arena/CLAUDE.md` and `docs/bot-arena.md`.
- `analyzer/main.cpp` — `BagiMahjongAnalyzer`, see `src/Mahjong/Analyzer/CLAUDE.md` and `docs/ev-analyzer.md`; it reads the files and `-` (stdin) and hands them to `RunAnalyzerCli`.
- `server/` — `main.cpp` of `BagiMahjongServer` (see `src/Mahjong/Online/CLAUDE.md`) and the Railway IaC partial `mahjong-rooms` for the service `bagi-mahjong-rooms`: `.railway/railway.ts`, `package.json` pinning the SDK, `package-lock.json` a copy of `web/`'s (only the name differs). Deploy: `docs/web.md`.
- `ui_shots.py` — nine UI scenes (`01-fresh-table` ... `07-options`, `08-rules` through `Options` then its `Rules` button, `09-online` through `New game` then `SetupOnline`) from `BagiMahjong --headless --control --manual-clock`, named `<NN>-<scene>-<W>x<H>.png` plus a copy scaled to 640 on its longer side. `--exe`, `--label`, `--out` (a folder outside the repository; the tool refuses one inside a git work tree; default `~/.claude/plans/mahjong-ui-skin-shots`), `--window WxH` (default `1920x1080`). The size is the headless window's and no control call changes it, so another size is made by a **temporary** `config/SDLWindowConfig.xml` of the game, written for the run and removed in a `finally` (also on Ctrl-C and SIGTERM); the tool refuses to start when that file already exists and never writes it for the default size. Pictures are never committed; `git status` is clean after a run.
- `collect_logs.py` — copies the match logs of testers that replay from `--from` folders into `logs/collected/` (`--to`), each once (SHA-256 of the bytes), with `index.json`; it asks `BagiMahjongArena --logs DIR --check` (`--verifier`, replaceable by any program that prints that format) and **never hides a drop**: a log that does not replay is not copied, goes to the index as `dropped` with the reason and is counted and listed in the summary; `--recheck` re-verifies the kept ones after a rules change. Refuses a `--to` that git would track. `--store URL` downloads the matches of the web service (`--user` + `$MATCH_STORE_PASSWORD` Basic, or `$MATCH_COLLECT_TOKEN` as Bearer) to `logs/downloaded/` and runs them through the same flow; a match is deleted on the server only after its file is read back equal, one that may still be played waits as `<id>.part` (the flow does not read it: one log per id) and is deleted, and becomes `.jsonl`, when it ends or after `--idle-hours` unchanged (`state.json`); a `tester` member of the list is kept in the index; `--delete-id`, `--forget-nickname`. Exit 0 / 1 (verifier missing or failing, a failed request) / 2. Test: `tests/collect_logs_test.py` (ctest `MahjongCollectLogs`). `docs/tester-match-logs.md`.
- `make_tiles.py` — the tile art (below).
- `make_emblems.py` — the seat emblems (below).
- `make_icons.py` — the UI icons (below).
- `make_app_icons.py` — the icons of the web app (`web/icons/`, listed in `web/app.json`): the Red Dragon cell of the atlas on `kFelt`, scaled to 192 and 512. Run it after a change of the art; `--check` compares the pixels.
- `web_smoke.py` — the browser smoke of the packaged page (`engine/tools/web/package.py --game BagiMahjong`). Needs Playwright (venv `build/web-venv`, `engine/tools/web/CLAUDE.md`, "The browser smoke") and a browser (`--browser-channel chrome` needs no download). `python tools/web_smoke.py --dist dist --browser-channel chrome --expect-console "Initialized with \d+ worker threads"` (`dist-single` with `"single-thread mode"`); exit 0 / 1 / 77 / 2 as the engine's. A fresh page first asks the upload question over `Setup` (`config/nodes/MahjongConsent.xml`): every scenario answers it with Don't send (`CONSENT_CLICK`, `--consent-click`) before Start. It runs the engine's checks with that click, then a second page load: Start, wait until the table stands still, click the first tile of the hand, the picture must change; then a third (a new browser context, an empty IndexedDB): Start, the table stands still, **reload**, a clip of the `Setup` plate (`PLATE_REGION`) must differ from the first load's (`Continue` is there), a click on `Continue` must change the picture (the saved match shown). East is a dice draw, so the person may face a claim window and not be first to act: the scenario presses the places of the action buttons (`CLAIM_ANSWER_CLICKS`) when a tile click does nothing and clicks the tile again; no outcome of the first move is assumed. The coordinates are for a 1280 x 720 window (`--start-click`, `--continue-click`, `--tile-click` replace them); **when Setup changes, re-check `START_CLICK`, `CONTINUE_CLICK` and `PLATE_REGION`** (Start is placed to stay in its button with or without the `Online` button) (`mahjong-setup-options` moves it, whoever merges second). `--check` runs the browser-free helpers; `--tile-click 5,5` must exit 1.

## Tile art

Our own art (owner decision: no third-party tile set, no font file). The script is a small software rasterizer with a 5x7 bitmap font of our own and one function per face; the art *is* the script.

- `python3 tools/make_tiles.py` writes `assets/tiles/tiles.png` and `config/TextureLibrary.xml`. **Run `--check` after every change** (compares decoded pixels and the XML, and checks the cells: all different, opaque middle, transparent corners, an index on every face and no art under it, the stack solid in its square and nothing outside it).
- `--preview OUT.png` (outside the repository) writes a contact sheet at four sizes for judging readability.
- Atlas: 8 x 6 cells of 96 x 128 (44 drawn), cell = tile id, cell 42 the back, cell 43 `Tile_Stack`: a wall stack seen from above, a `STACK_SIZE` (96) square at the top left of its cell, the rest transparent (the sprite is the square; `StackRect()`). `CELL_W`, `CELL_H`, `COLUMNS` are the one place of the geometry and must match `src/Mahjong/Table/TileAtlas.h` (`TileSpritesTest`).
- A tile is a block: the ivory side shows `SIDE_BOTTOM` / `SIDE_RIGHT` units (2.5 to 3 px at discard size) below and right of the face, in three bands (`SIDE_LIGHT`, `SIDE`, `SIDE_SHADE`); the back has the same side. The patterns are laid out in `ART_FACE` and mapped into the smaller `BODY_FACE` by `art_view`, so a change of the side width moves `ART_SCALE`, not the layouts. Never loosen `index_problems`: shrink the art.
- Every face but the back has a corner index (`INDEX_PIXEL`, `INDEX_X`, `INDEX_Y`, `INDEX_BOX`) so a tile reads at discard size (24 x 32); the art is drawn scaled by `ART_SCALE` to leave room for it. The White dragon's index is a hollow frame (a `W` would read as West).

## Emblem art

`python3 tools/make_emblems.py` writes `assets/emblems/emblems.png` (4 x 4 cells of 64: the person, the computer of level 1..10 with its numeral, the white turn ring, the white dotted calling ring; one shared centre, the rings outside the emblem disc). It imports `Canvas`, the font and the PNG encoder of `make_tiles.py` (and adds the digit `0` to its font at run time). **Run `--check` after a change** (decoded pixels, cells all different, transparent corners, an opaque middle, rings clear inside and white, no emblem pixel on the rings' ground); `--preview OUT.png` (outside the repository) shows the cells at the real size and four times, and the rings tinted over an emblem. The cell numbers and `DISC_RADIUS` must match `src/Mahjong/Table/EmblemAtlas.h` (`EmblemSpritesTest`). The whole `assets/` folder reaches the build and the web package, so a new asset needs no line elsewhere.

## Icon art

`python3 tools/make_icons.py` writes `assets/icons/icons.png` (4 x 2 cells of 64: `ICON_NAMES`, row by row; white on transparent, so the scene's `tint` colours an icon; each keeps `ICON_MARGIN` clear of its cell's edge). It imports `Canvas` and the PNG encoder of `make_tiles.py`. The sprites `Icon_<name>` are in `config/TextureLibrary.xml`, which **`make_tiles.py` writes** (the whole file, tiles first, then `make_icons.sprite_entries()`): after a change of the icons run both scripts. **Run `--check` after a change** (decoded pixels, cells all different, white only, solid, transparent corners and margin, the XML equal to what `make_tiles.py` makes); `--preview OUT.png` (outside the repository) shows the cells at 24, 56 and 112 px. The numbers must match the copy in `tests/IconSpritesTest.cpp`; the scene names a sprite by its library name, so there is no C++ header.
